# Notification Copy Audit (Inventory)

Complete inventory of every notification **title** and **body** string constructed across
`services/` and `app/api/` (plus `app/actions/`, which contains server actions that fire
notifications). This is a **read-only inventory** — no copy has been rewritten.

## How copy is stored

Copy lives in **two places**:

1. **Centralized copy builders** — `lib/notification-copy.ts` exports functions that return
   `{ title, body }` (e.g. `shiftStartedSelf`, `whaleRegisteredAdmin`, `fineIssuedPersonal`,
   `modelLiveStartedChatter`, `sopQuizPassedPersonal`, …). It also exports `buildAdminTitle` /
   `buildAdminBody`, which produce the paired `_admin` variant copy for role-config broadcasts.
2. **Inline at the call site** — most `notify()` / `notifyAdmins()` / `notifyByRoleConfig()`
   calls pass `title:` / `body:` string literals (often template strings) directly.

The core send functions (`notify`, `notifyAdmins`, `notifyAdminsOnce`, `notifyByRoleConfig`,
`notifyAllUsers`) live in `services/notification-service.ts` and do **not** define copy
themselves — they forward the caller-supplied `title`/`body`. When `notifyByRoleConfig` fires a
paired `_admin` event, the admin copy is generated by `buildAdminTitle` / `buildAdminBody`
in `lib/notification-copy.ts` (see the "Admin-variant copy" section).

Variable interpolation is shown verbatim (e.g. `${name}`, `${count}`, `{weekLabel}`).

## Admin-variant copy (centralized) — reference

`notifyByRoleConfig` auto-fires a paired `<event>_admin` for events with an admin variant
(`lib/notification-admin-variants.ts`). Copy is produced by `buildAdminTitle` / `buildAdminBody`
in `lib/notification-copy.ts` using the `context` object passed at the personal call site. The
fallback (when no case matches) is:

- Title: `fallbackTitle` (the personal title) or `${actor} — ${baseEventType.replace(/_/g, " ")}`
- Body: `fallbackBody` (the personal body) or `${actor}. Models: ${modelList}.`

Custom-approved admin body: `Custom request του ${ctx.fanUsername ?? "fan"} εγκρίθηκε. Model: ${ctx.modelName ?? "—"}, Τιμή: ${ctx.price ?? "—"}` (title `Custom εγκρίθηκε — ${ctx.modelName ?? "model"}`).

Period-overdue admin: `Περίοδος — ${name}` / `${name} δεν έχει καταχωρήσει περίοδο`.
Form-submitted admin: `📋 Form submitted` / `📋 ${formName} from ${actorName} at ${t}.`

## Observations (wording only — not changed)

- **Mixed languages.** Fines/bonuses, mistakes, spin results, SOP quiz, period overdue,
  schedule-published, login/password, and several admin-variant strings are in **Greek**
  (e.g. `Σου επιβλήθηκε πρόστιμο`, `Κέρδισες …! 🎉`, `Πρόγραμμα δημοσιεύτηκε`), while the
  majority of the app (winner videos, creative scripts, spot checks, whales, shifts,
  billing, custom requests) is in **English**. This inconsistency is per-feature, not global.
- **Emoji usage is inconsistent.** Most operational copy is emoji-prefixed (`🟢`, `⚠️`, `📅`),
  but several strings have none (winner videos, creative scripts, spot checks, fines/bonuses
  Greek copy, `Winner video approved`, `New spot check logged`). Some prefix both title and
  body with the same emoji (double emoji on lock screen), e.g. shift/break copy.
- **Raw reason strings used as body.** `winner_video_rejected`, `creative_script_rejected`,
  `tip_rejected`, `rebill_rejected`, `expense_rejected` set `body` directly to the reviewer's
  free-text note (or a terse fallback like `No reason provided.` / `Your tip was rejected.`),
  so body quality depends entirely on the admin's input.
- **Robotic / terse entries.** `📝 Status: ${admin_status}.`, `body: reason` (bare), `No reason
  provided.`, `📋 An admin asked you to review this task.`, and `❌ ${modelName} cancelled a
  pending time-off request (record ${recordId}).` (leaks the raw Airtable record id) read as
  developer-facing rather than user-facing.
- **Near-duplicate copy across channels.** `custom_scheduled` and `custom_uploaded` have
  3–4 slightly different title/body variants across `app/api/model/custom/*`,
  `app/api/client/content/*`, and `app/actions/model-custom-requests.ts` that could drift.
  Likewise `va_task_assigned` copy is duplicated verbatim in `services/task-templates.ts`
  and `app/actions/va-tasks.ts`, and `spot_check_logged` copy is duplicated in
  `services/marketing-reviews.ts` (two functions).
- **`system_alert` overloaded.** Many distinct events (feedback, rebill submitted, extra
  revenue, expense submitted, time off, period started, billing revenue/due, shift-queue
  errors, prize claimed) are all sent under the generic `system_alert` event type with
  bespoke inline titles, rather than dedicated event types.
- **Currency/format inconsistency.** Amounts appear as `$${x.toFixed(2)}`, `€${whaleTotal}`,
  `${amt}€`, and `💰 ${amount}` across billing, fines, tips, and whale copy.
